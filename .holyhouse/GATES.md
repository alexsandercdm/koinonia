# Quality Gates

Every meaningful change must pass these gates before being called complete.

## Gates

- Intent gate: the requested outcome is restated and understood.
- Context gate: relevant docs, code, state, and prior decisions were read.
- Plan gate: implementation steps are explicit enough to verify.
- Execution gate: changes are small, scoped, and reversible.
- Verification gate: tests, checks, or manual validation prove the result.
- Documentation gate: memory, decisions, state, or docs are updated when the project learned something.
- Handoff gate: final status includes what changed, what passed, and what remains risky.
