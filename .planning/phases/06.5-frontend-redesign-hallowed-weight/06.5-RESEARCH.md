## Summary

A Phase 6.5 é uma **substituição completa** do design system, não um patch. O sistema atual (Stitch: dark/purple/amber) está codificado em três camadas: `tailwind.config.js` (tokens hardcoded), `index.css` (HSL variables Midnight Koinonia), e `AppLayout.tsx` (dimensões e tokens Stitch inline nas classes). Todas as três precisam ser reescritas.

O roteador atual é **react-router-dom v6** (confirmado em `App.tsx` e `package.json`), não TanStack Router. A rota `/eventos/selecionar` (UX-05) deve ser adicionada com `<Route>` padrão do react-router. O contexto de evento selecionado precisa ser gerenciado via React Context ou estado elevado — nenhum gerenciador de estado global existe hoje além do TanStack Query.

Os artifacts de referência completos estão em `doc/Koinonia-redesign/` — os JSX ali são a fonte canônica de implementação. As 12 primitivas usam inline styles no JSX de referência; a tradução para Tailwind tokens é o trabalho desta fase (D1 locked).

**Primary recommendation:** Executar em 4 waves sequenciais: (1) Foundation/tokens, (2) Primitivas ui-hw, (3) AppShell + rotas, (4) Migração de páginas.

### Pattern 1: Token Translation (D1 — inline style → Tailwind class)

O JSX de referência usa inline styles com o objeto `C`. A tradução obrigatória (D1 locked):

```tsx
// Referência (koinonia-primitives.jsx)
// background: C.text → bg-text
// color: C.textSec → text-text-sec
// border: `1px solid ${C.border}` → border border-border
// borderRadius: 7 → rounded-btn
// padding: '8px 16px' → py-2 px-4 (ou px-[main-pad])
```

**Regra:** Qualquer inline style do JSX de referência deve virar classe Tailwind usando os tokens registrados. Exceções permitidas apenas para valores one-off explicitamente documentados (ex: frame do CheckinOverlay: `44px`).

### Pattern 2: Icon Primitive

```tsx
// Source: doc/Koinonia-redesign/koinonia-primitives.jsx L17-25
// Tradução Tailwind:
function Icon({ name, size = 20, fill = false, className = '' }: IconProps) {
  return (
    <span
      className={cn(
        'material-symbols-outlined leading-none',
        fill && 'font-variation-fill-1', // custom CSS var
        className
      )}
      style={{ fontSize: size }}
    >
      {name}
    </span>
  )
}
```

Para fill: `fontVariationSettings: "'FILL' 1"` — já usado no AppLayout.tsx atual (linha 56). Manter pattern.

### Pattern 3: EventContext para estado do evento selecionado

```tsx
// NOVO: apps/web/src/contexts/event-context.tsx
// State: selectedEventoId (string | null)
// Persistence: localStorage.koinonia.selectedEventoId + URL ?eventoId=X
// Consumption: EventPill lê, EventSelectorScreen escreve
```

### Anti-Patterns a Evitar

- **Não usar `class="dark"` no html**: remover do `index.html` — HW é sistema light
- **Não usar `transform: scale()` em hover**: banido pelo UI-SPEC (seção Hover)
- **Não usar `outline: none` sem replacement**: toda interação precisa de focus ring visível
- **Não usar gold em CTAs primários**: primary button é `bg-text` (near-black), não gold
- **Não introduzir `font-black`** em nenhuma classe nova
- **Não usar tokens Stitch** (`surface-dark`, `border-dark`, etc.) em nenhum componente novo

## Common Pitfalls

### Pitfall 1: Remover lucide sem auditoria completa
**O que dá errado:** Alguns imports de lucide podem estar em componentes de `apps/web/src/components/` não listados na busca por páginas.
**Como evitar:** Antes de remover o pacote, rodar `grep -r "lucide-react" apps/web/src/ --include="*.tsx" --include="*.ts"` e confirmar lista zero antes de `pnpm install`.
**Lista atual confirmada:** 6 arquivos: `dashboard.tsx`, `login.tsx`, `register.tsx`, `FinanceiroPage.tsx`, `InscricoesPage.tsx`, `ParticipantsPage.tsx`.

### Pitfall 2: gold overuse (>5 ocorrências por página)
**O que dá errado:** Páginas que migram badges, links editoriais e ícones simultaneamente podem facilmente ultrapassar 5 usos de gold.
**Como evitar:** Após migração de cada página, rodar: `grep -c "text-gold\|bg-gold\|border-gold\|gold-light\|gold-muted" apps/web/src/pages/<Page>.tsx`. Se >5, revisar e justificar.
**Regra:** No máximo 1 KPI gold por dashboard view.

### Pitfall 3: AppShell sem EventPill em rotas públicas
**O que dá errado:** EventPill retorna null quando nenhum evento está selecionado, mas o AppShell precisa ser montado em TODAS as rotas autenticadas.
**Como evitar:** AppShell deve ser o wrapper de `ProtectedRoute` ou equivalente, não de rotas públicas. Login e Register ficam fora do AppShell.

### Pitfall 4: max-w-[1100px] esquecido nas páginas migradas
**O que dá errado:** Páginas ficam com layout full-width (herança Stitch), criando inconsistência visual.
**Como evitar:** Checklist de migração por página: verificar presença de `max-w-[1100px] mx-auto` no wrapper do conteúdo. Exceção: AcomodacoesPage map view.

### Pitfall 5: DM Sans não carregada → fallback system-ui
**O que dá errado:** Peso 300 (Display heading de login) fica com fallback errado.
**Como evitar:** Carregar DM Sans com pesos explícitos (300/400/500/600/700 + 400 italic) via preconnect + stylesheet em `index.html` ANTES de `tailwind.config.js` configurar `fontFamily.sans`.

### Event Context

```tsx
// apps/web/src/contexts/event-context.tsx (novo)
const STORAGE_KEY = 'koinonia.selectedEventoId'

export function EventProvider({ children }: { children: React.ReactNode }) {
  const [selectedEventoId, setSelectedEventoId] = React.useState<string | null>(
    () => localStorage.getItem(STORAGE_KEY)
  )

  const selectEvento = (id: string) => {
    localStorage.setItem(STORAGE_KEY, id)
    setSelectedEventoId(id)
  }

  return (
    <EventContext.Provider value={{ selectedEventoId, selectEvento }}>
      {children}
    </EventContext.Provider>
  )
}
```
