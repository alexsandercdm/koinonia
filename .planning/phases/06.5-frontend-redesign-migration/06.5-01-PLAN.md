<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-provided text -> UI primitives | Labels, hints, errors, option text, and empty-state copy are rendered in reusable components |
| Focus/keyboard navigation -> custom controls | `FilterTabs` turns filter state into interactive segmented buttons |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06.5-01-01 | Spoofing | `Button` / `Badge` semantic variants | low | mitigate | Keep destructive, warning, success, info, and neutral styles visually distinct. Do not use gold as a universal status color. |
| T-06.5-01-02 | Tampering | `FilterTabs` option values | low | mitigate | `FilterTabs` only emits the selected string value through `onValueChange`; page-level code remains responsible for filtering and must not construct API paths directly from tab values without validation. |
| T-06.5-01-03 | Denial of Service | Long labels in buttons/tabs/empty states | medium | mitigate | Use flex wrapping/truncation where needed and maintain stable control heights. Later page plans must verify mobile widths. |
| T-06.5-01-04 | Information Disclosure | Form helper/error text | low | accept | Primitive displays caller-provided strings only. Auth/API errors must pass sanitized `error.message`, not raw response bodies. |
</threat_model>
