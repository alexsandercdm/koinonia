# Phase 6.5: Frontend Redesign Migration - Pattern Map

**Mapped:** 2026-04-26
**Status:** Ready for planning

## Source Contracts

- `doc/Koinonia-redesign/uploads/design-philosophy-hallowed-weight.md` defines the visual direction: warm light background, white surfaces, deep brown/black text, restrained gold accent.
- `doc/Koinonia-redesign/koinonia-primitives.jsx` defines target primitive behavior and naming, but it is prototype code with inline styles.
- `doc/Koinonia-redesign/koinonia-layout.jsx` defines the target shell shape: sidebar, compact header, event context, user area, and responsive nav behavior.
- `doc/Koinonia-redesign/koinonia-pages-main.jsx` defines visual hierarchy for dashboard, participants, inscriptions, and finance.
- `doc/Koinonia-redesign/koinonia-page-login.jsx` defines the editorial auth screen direction.
- `doc/Koinonia-redesign/koinonia-page-acomodacoes.jsx` defines accommodation visual treatment.
- `doc/Koinonia-redesign/koinonia-data.jsx` defines status color semantics.

## Runtime Anchors

| Target | Existing File | Closest Pattern | Planning Notes |
|--------|---------------|-----------------|----------------|
| Global tokens | `apps/web/src/index.css` | CSS custom properties under `:root, .dark` | Replace dark-violet HSL values with Hallowed Weight HSL tokens. Keep semantic token names so existing shadcn-like primitives continue to work during migration. |
| Tailwind theme | `apps/web/tailwind.config.js` | `theme.extend.colors` semantic tokens plus old Stitch aliases | Remove or stop depending on `surface-dark`, `background-dark`, `border-dark`, `amber-accent`. Add warm aliases only if needed for transition. Preserve current ESM config shape. |
| Button primitive | `apps/web/src/components/ui/button.tsx` | CVA-like hand-coded variant map using `cn` | Extend variants instead of introducing a new dependency. Add `primary`, `gold`, `danger`, `secondary`, `ghost` while preserving compatibility with existing `default`, `destructive`, `outline`, `link`. |
| Card primitive | `apps/web/src/components/ui/card.tsx` | Simple forwardRef components | Keep 8px default radius, warm border, white/raised surfaces. Avoid nested card patterns in page plans. |
| Form fields | `apps/web/src/components/ui/input.tsx`, `label.tsx` | shadcn-like field primitives | Add missing `Select`, `TextArea`, and `FormField` only if pages need them. Preserve native form behavior and React Hook Form usage in auth pages. |
| Drawer/sheet | `apps/web/src/components/ui/sheet.tsx` | Radix Dialog wrapper | Use existing sheet for right-side desktop drawers and full-width mobile sheets. Do not add a second drawer abstraction. |
| Shell | `apps/web/src/components/layout/AppLayout.tsx` | Central authenticated layout with `NAV_ITEMS`, `useNavigate`, `useLocation`, `useAuthContext`, `title`, `actions` | Preserve route paths, title/actions API, user/logout behavior. Replace fixed mobile-hostile dark sidebar with responsive warm-light shell. |
| Auth pages | `apps/web/src/pages/login.tsx`, `register.tsx` | React Hook Form + Zod + `useAuthContext` | Restyle only. Preserve `login(data.email, data.password)`, `registerUser(data.email, data.password, data.name)`, loading/error states, and redirects to `/dashboard`. |
| Dashboard | `apps/web/src/pages/dashboard.tsx` | TanStack Query + `apiFetch` live data | Keep queries and route navigation. Replace dark hero/card styling with event summary, metric cards, recent inscriptions, quick actions. Do not swap live data for mock data. |
| Participants | `apps/web/src/pages/ParticipantsPage.tsx` | Local search/filter over `apiFetch('/api/v1/participantes')` | Visual migration only. Keep query key `['participantes']`, local filtering, loading/error/empty states. Full CRUD waits for Phase 7. |
| Inscriptions | `apps/web/src/pages/InscricoesPage.tsx` | `useEventos`, `useInadimplentes`, selected event state, filters, table | Restyle event selector, metrics, status badges, filters, table/mobile list. Do not add new payment/inscription mutation scope. |
| Finance | `apps/web/src/pages/FinanceiroPage.tsx` | Finance metrics/despesas queries and existing create expense modal | Restyle metric/report surfaces and modal. Do not add new export workflow. Preserve mutation/query invalidation. |
| Accommodation page | `apps/web/src/pages/AcomodacoesPage.tsx` | Event selector, tab state, role-based write behavior, assign sheet | Restyle tabs, filters, event selector, empty/error/loading states. Preserve `canWrite`, selected cama flow, and sheet wiring. |
| Accommodation components | `apps/web/src/components/acomodacoes/*.tsx` | Existing bed-card, map-grid, filters, structure, export button | Treat as domain-critical. Only visual changes unless current styling blocks the redesign. Preserve query/mutation keys and export behavior. |

## Stale Patterns to Remove During Execution

The executor should progressively remove runtime dependency on these Phase 5 tokens/classes:

- `bg-background-dark`
- `bg-surface-dark`
- `bg-surface-elevated`
- `border-border-dark`
- `text-violet-*`
- `text-purple-*` for primary system states
- `amber-accent`
- literal `#4d0085`
- literal `#1b0f23`
- literal `#0f0814`
- literal `#ffbf00`

## Non-Regression Anchors

- `apps/web/src/App.tsx` must keep protected routes for `/dashboard`, `/participantes`, `/inscricoes`, `/acomodacoes`, `/financeiro`.
- `apps/web/src/contexts/auth-context.tsx`, `apps/web/src/components/protected-route.tsx`, `apps/web/src/lib/auth.ts`, and `apps/web/src/lib/api.ts` are auth/session boundaries; read them before auth/shell edits.
- `apps/web/src/hooks/use-acomodacoes.ts` and `apps/web/src/hooks/use-inscricoes.ts` are data contract boundaries for pages. Read before changing page state or query behavior.
