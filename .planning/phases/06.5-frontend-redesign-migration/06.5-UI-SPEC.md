# Phase 6.5 — UI Design Contract

> Visual and interaction contract for the frontend redesign migration. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

Phase 6.5 migrates the existing frontend from the Phase 5 dark Stitch baseline to the `doc/Koinonia-redesign` "Hallowed Weight" direction. This phase must change visual system, shell, primitives, responsive behavior, login/register styling, and existing page presentation without adding new CRUD capabilities.

Runtime contracts remain canonical:

- Better Auth login/register/session behavior remains unchanged.
- Protected routes remain `/dashboard`, `/participantes`, `/inscricoes`, `/acomodacoes`, `/financeiro`, `/login`, and `/register`.
- TanStack Query and `apiFetch` remain the server-state and HTTP boundary.
- Existing accommodation, participant, registration, and finance domain behavior must not be replaced with prototype mock data.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Manual Tailwind primitives; no shadcn CLI initialization in this phase |
| Preset | Not applicable |
| Component library | Existing shadcn-like primitives plus Radix primitives already installed |
| Icon library | `lucide-react` for React components; Material Symbols may remain only where already embedded and should be normalized opportunistically |
| Font | Inter or current app sans-serif stack; do not add a new font dependency unless already available |

Design-system rationale:

- `components.json` is not present, so shadcn is not initialized.
- The repo already has reusable primitives in `apps/web/src/components/ui` and Radix packages in `apps/web/package.json`.
- Phase 6.5 should adapt the existing primitives instead of introducing a new registry or dependency path.

Required primitives for this phase:

| Primitive | Contract |
|-----------|----------|
| `Button` | Variants: `primary`, `secondary`, `ghost`, `danger`, `gold`; min touch target 48px for page actions and auth submit buttons |
| `Badge` | Variants: `gold`, `success`, `warning`, `danger`, `info`, `neutral`; Label typography role; pill shape only for status metadata |
| `Input` / `Select` / `TextArea` | White surface, warm border, gold focus ring, inline error text below field |
| `FormField` | Label, required marker, hint/error slot; label text must not be embedded ad hoc in page components |
| `Card` | White or raised surface, warm border, 8px radius default |
| `Drawer` / `Sheet` | Right-side desktop drawer and full-width mobile sheet; warm overlay; explicit close button with accessible label |
| `SectionTitle` | Uppercase micro-label for grouped operational sections only |
| `FilterTabs` | Segmented filter controls for participant, accommodation, and payment status filters |
| `EmptyState` | Icon, heading, body, and optional action; never use a generic no-data sentence alone |

## Spacing Scale

Declared values:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding adjustments, field helper spacing |
| sm | 8px | Compact element gaps, button icon gap, table cell inner rhythm |
| md | 16px | Default component spacing, form groups, card internal gaps |
| lg | 24px | Page section padding, drawer body padding, mobile page gutters |
| xl | 32px | Desktop page gutters, dashboard grid gaps |
| 2xl | 48px | Auth panel breathing room, major section breaks, minimum touch target |
| 3xl | 64px | Empty-state vertical padding and large desktop editorial spacing |

Exceptions: none.

Layout rules:

- Use `24px` page gutters on mobile and `32px` on desktop by composing the declared scale, not by introducing new spacing tokens.
- Prototype-specific border-radius values are implementation references, not spacing scale additions.
- Icon-only actions must keep a visible or `aria-label` fallback and a 48px interactive hit area where they are primary or navigation actions.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 600 | 1.3 |
| Body | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 400 | 1.15 |

Typography rules:

- Use only weights `400` and `600` in runtime UI for this phase.
- Do not use `font-black`, oversized dashboard hero text, or negative tracking from the Phase 5 dark baseline.
- Login editorial copy may use the Display role and italic emphasis, but should remain readable on mobile and must not become a marketing landing page.
- Dense operational panels may use Label for metadata, but primary data values should remain Body or Heading.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F4EF` | App background and broad page canvas |
| Secondary (30%) | `#FFFFFF`, `#FDFCFA`, `#E8E3D9` | Cards, sidebar, header, drawers, fields, table surfaces, borders |
| Accent (10%) | `#C4923A` | Active event context, focus rings, selected filters, active nav indicator, small sacred emphasis marks |
| Text foundation | `#1A1612` | Main text and primary filled button background |
| Secondary text | `#7A7060` | Descriptions, metadata, secondary nav labels |
| Tertiary text | `#B0A898` | Placeholders, timestamps, muted helper text |
| Destructive | `#9B3A2E` | Destructive actions and danger badges only |

Accent reserved for:

- Active navigation marker.
- `EventPill` active state and event dropdown selected item.
- Focus ring and focused input border.
- Selected `FilterTabs` state.
- Small editorial rule or emphasis mark on login/register.
- Gold status badges where the semantic state is neutral-highlight, not success/warning/danger.

Semantic status map:

| Meaning | Text | Background |
|---------|------|------------|
| Success / paid / available | `#3D7A52` | `#E8F4ED` |
| Warning / partial / attention | `#B07030` | `#FBF0E2` |
| Danger / blocked / overdue | `#9B3A2E` | `#FBECEC` |
| Info / in progress | `#2E628B` | `#E8F2FA` |
| Neutral | `#7A7060` | `#F0EDE8` |

Color migration rules:

- Replace Phase 5 tokens and classes such as `background-dark`, `surface-dark`, `border-dark`, `amber-accent`, `#4d0085`, `#1b0f23`, and `#ffbf00`.
- Do not scatter hex values through page components after tokens/primitives exist.
- Do not use gold for every clickable element; primary destructive and semantic states must keep their own colors.

## Visual Hierarchy

Primary focal point:

- Auth screens: editorial brand statement on desktop; auth form title and first field on mobile.
- Authenticated shell: page title plus `EventPill` in the header, followed by page actions.
- Dashboard: current event summary and the first row of operational metrics.
- Participants: search input and filter tabs, then the participant list.
- Inscricoes and Financeiro: status/metric summary first, then tables/lists.
- Acomodacoes: map/structure tabs and occupancy status, then room/bed content.

Composition rules:

- The application is an operational tool, not a marketing site. Avoid decorative hero sections, dark gradients, blurred blobs, oversized cards, and stock-like atmospheric media.
- Page sections should be unframed layouts or repeated item cards, not cards nested inside larger cards.
- Mobile navigation must expose all primary routes without relying on a fixed desktop sidebar.
- Tables must have a mobile treatment: responsive cards/list rows or controlled horizontal overflow with visible context.
- Loading, error, empty, and offline-grace states must visually match the warm-light system.

---

## Interaction Contract

Shell and navigation:

- `AppLayout` must preserve `title` and `actions` props.
- Desktop shell should use a restrained sidebar plus compact header.
- Mobile shell should use a drawer, top navigation, or bottom navigation; all primary routes must remain reachable within one interaction from any protected page.
- Logout remains available from the authenticated user area and must call the existing `logout` from `useAuthContext`.

Event context:

- Include an `EventPill` visual affordance in the header.
- In this phase, `EventPill` may use local or existing event data only; it must not imply new event CRUD behavior before Phase 8.
- "Novo evento" may be omitted or presented as disabled/non-primary if no backend action is wired.

Forms:

- Fields use warm borders, gold focus, inline validation, and visible labels.
- Auth submit buttons must show loading copy and spinner icon while Better Auth is pending.
- Password visibility toggles need accessible labels.

Responsive behavior:

- Baseline check widths: 390px, 768px, 1280px.
- Minimum primary action hit area: 48px.
- Drawers become full-width sheets on mobile.
- Header actions can collapse into an overflow menu on mobile if needed.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Login primary CTA | Entrar no painel |
| Register primary CTA | Criar minha conta |
| Dashboard primary CTA | Ver participantes |
| Participants primary CTA | Adicionar participante |
| Acomodacoes primary CTA | Atribuir cama |
| Event context label | Evento ativo |
| Empty state heading | Sua busca não trouxe registros para esta etapa |
| Empty state body | Ajuste os filtros ou use a ação principal da página quando a etapa funcional correspondente estiver disponível. |
| Error state | Não foi possível carregar os dados. Verifique sua conexão e tente novamente. |
| Offline state | Sem conexão. Os dados em cache continuam disponíveis enquanto a conexão é restabelecida. |
| Destructive confirmation | Desativar participante: confirme que o histórico de inscrições deve ser preservado antes de continuar. |

Copy rules:

- Do not use generic CTA labels; every action label needs a specific verb and object.
- Portuguese labels are the runtime default.
- Empty states must include the user's next step.
- Error states must include a recovery path.
- Destructive copy must name the object and outcome.

| Acomodacoes | Restyle map/structure, bed cards, filters, assign sheet, export button; do not change assignment or export logic |

## Verification Contract

Required static checks:

- `pnpm --filter @koinonia/web type-check`
- `pnpm --filter @koinonia/web build`
- Grep for stale dominant tokens: `background-dark`, `surface-dark`, `border-dark`, `amber-accent`, `#4d0085`, `#1b0f23`, `#ffbf00`

Required behavior checks:

- Unauthenticated protected route redirects to `/login`.
- Login form still calls Better Auth through `useAuthContext().login` and navigates to `/dashboard`.
- Register form still calls Better Auth through `useAuthContext().register` and navigates to `/dashboard`.
- Authenticated navigation reaches `/dashboard`, `/participantes`, `/inscricoes`, `/acomodacoes`, and `/financeiro`.
- Dashboard and feature pages continue using TanStack Query or existing hooks, not prototype mock arrays.

Required responsive checks:

- 390px mobile: login/register, shell navigation, dashboard, participants, and accommodations do not overlap or require desktop sidebar.
- 768px tablet: header actions and event context remain reachable.
- 1280px desktop: sidebar, header, page body, and drawers align to warm-light system.
