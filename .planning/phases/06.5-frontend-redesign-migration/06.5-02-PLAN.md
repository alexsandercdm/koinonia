<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser session -> authenticated shell | `AppLayout` renders user name/email and exposes logout |
| Unauthenticated user -> Better Auth login/register | Auth forms collect credentials and call Better Auth through `AuthProvider` |
| Route navigation -> protected pages | Sidebar/mobile nav routes must respect `ProtectedRoute` wrappers in `App.tsx` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06.5-02-01 | Spoofing | EventPill | medium | mitigate | EventPill must be visual/local or based on existing event data only. Do not present create/edit event actions as functional before Phase 8. |
| T-06.5-02-02 | Information Disclosure | User area in shell | low | mitigate | Render only existing `user.name` and `user.email`. Do not expose role claims, session token, or raw session payload. |
| T-06.5-02-03 | Elevation of Privilege | Mobile/desktop navigation | high | mitigate | Navigation is only links to existing protected routes. Do not remove `ProtectedRoute` in `App.tsx` and do not add route bypasses. |
| T-06.5-02-04 | Spoofing | Auth forms | high | mitigate | Preserve `useAuthContext().login/register` calls and `/dashboard` redirects. Do not introduce direct fetch/JWT/Supabase auth flows. |
| T-06.5-02-05 | Denial of Service | Mobile shell layout | medium | mitigate | Mobile nav must not trap content behind fixed sidebar. Verify 390px width for route reachability and no header/action overlap. |
</threat_model>
