<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Accommodation API data -> bed map UI | Room/bed/participant/status data drives operational assignment decisions |
| Auth role -> write capability | `admin`/`lider` can assign/release beds; `servo` receives read-only behavior |
| UI action -> assignment/export mutations | Existing callbacks and PDF export trigger domain-critical operations |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06.5-04-01 | Tampering | `AssignCamaSheet` / map actions | high | mitigate | Preserve existing props, mutation hooks, payloads, and query keys. Visual migration must not alter assignment or release semantics. |
| T-06.5-04-02 | Elevation of Privilege | `canWrite` and role-based accommodation editing | high | mitigate | Preserve role derivation and only pass assign/release callbacks when `userRole` is `admin` or `lider`. |
| T-06.5-04-03 | Information Disclosure | Accommodation map and participant names | medium | accept | Existing UI already renders operational assignment data. Do not add additional sensitive health or payment data to accommodation cards. |
| T-06.5-04-04 | Denial of Service | Final runtime visual migration | medium | mitigate | Type-check, build, stale-token grep, and responsive smoke checks are mandatory before phase completion. |
| T-06.5-04-05 | Repudiation | PDF export | medium | mitigate | Preserve `exportMapaAcomodacao` behavior and filename/event context. Do not silently change exported data fields in a visual migration. |
</threat_model>
