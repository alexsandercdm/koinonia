## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API data -> page UI | Participants, inscriptions, finance metrics, expenses, and event names render in page components |
| User filters/search -> local state | Search/filter values affect local rendering |
| Finance modal -> backend mutation | Existing expense form posts data to finance endpoint |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06.5-03-01 | Tampering | Dashboard/participants/inscriptions visual migration | high | mitigate | Preserve all existing `apiFetch` endpoints and query keys. Do not replace live query data with prototype mock data. |
| T-06.5-03-02 | Repudiation | Finance expense modal | medium | mitigate | Preserve existing mutation payload and invalidation behavior. Do not change audit-relevant finance workflow semantics in a visual phase. |
| T-06.5-03-03 | Information Disclosure | Health restrictions in participants cards | medium | mitigate | Preserve existing restriction display level only; do not add new sensitive health fields or expose raw API payloads beyond current UI. |
| T-06.5-03-04 | Denial of Service | Tables on mobile | medium | mitigate | Provide mobile cards or controlled horizontal overflow so operational screens remain usable at 390px. |
| T-06.5-03-05 | Elevation of Privilege | Page actions | high | mitigate | Do not add new CRUD buttons with working mutations beyond current behavior. Future create/edit/delete capabilities remain Phase 7-9. |
</threat_model>
