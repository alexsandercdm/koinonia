# 08-02 - Frontend design-system foundation for Eventos

<objective>
Align the shared UI primitives and tokens touched by Eventos with the approved Phase 8 UI-SPEC before building the page-specific UI.
</objective>

<threat_model>
This plan changes presentation primitives only. The main risk is broad UI regression from shared component changes. Mitigation: keep changes to UI-SPEC values, preserve component props/APIs, and run web type-check/build. Severity: low.
</threat_model>

<must_haves>
  <truths>
    - `doc/Design System Koinonia.html` and `08-UI-SPEC.md` are reflected in shared tokens/primitives.
    - Existing components keep their public props.
    - No new third-party registry or component dependency is introduced.
  </truths>
  <artifacts>
    - DM Sans font loading
    - warm token aliases including `goldMuted`
    - primitive class updates for Button, Badge, form controls, FilterTabs, Card, Sheet, EmptyState
  </artifacts>
  <key_links>
    - EventosPage and EventPill in later plans rely on these shared primitive contracts.
  </key_links>
</must_haves>

<decision_coverage>
- D-01: `doc/Design System Koinonia.html` is implemented as canonical visual source for touched primitives.
- D-02: legacy redesign JSX remains secondary to the HTML design system.
- D-03: Hallowed Weight baseline is refined into DM Sans, warm surfaces, restrained gold, smaller radius, and denser operational hierarchy.
- D-04: shared primitives are audited and adjusted before EventosPage implementation.
- D-05: tokens stay centralized in `index.css` and `tailwind.config.js`.
- D-06: touched shared UI is corrected instead of creating a local Eventos-only design language.
- D-07: unrelated page rewrites are excluded.
- D-08: DM Sans is loaded as the primary app font.
- D-09: Material Symbols Rounded remains the domain/navigation icon target.
- D-10: canonical design-system color tokens are exposed through shared tokens.
- D-19: Button variants follow the design-system contract.
- D-20: Badges follow the design-system contract.
- D-21: Inputs/selects/textareas follow the design-system contract.
- D-22: operational list/table styling is available through shared primitives.
- D-23: progress bar styling is available for Eventos cards.
</decision_coverage>
