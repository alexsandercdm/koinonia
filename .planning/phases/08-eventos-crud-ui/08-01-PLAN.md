# 08-01 - Backend event list contract and capacity aggregate

<objective>
Make `GET /api/v1/eventos` return a truthful event-list contract with occupied capacity data, while preserving admin-only create/update and aligning event date schemas with browser date inputs.
</objective>

<threat_model>
No new unauthenticated surface is introduced. Read endpoints remain behind `authMiddleware`; write endpoints remain behind `requireRole('admin')`. Capacity aggregate must count existing registrations without exposing participant health or payment details. Severity: low after preserving existing RBAC.
</threat_model>

<must_haves>
  <truths>
    - `GET /api/v1/eventos` returns `inscritos_count` and `ocupacao_percentual` for each event.
    - Event create/update route schemas accept `YYYY-MM-DD` date strings from frontend date inputs.
    - Event write RBAC stays admin-only.
    - Shared event list type lives in `packages/shared`.
  </truths>
  <artifacts>
    - `EventoListItemSchema`
    - `EventoListItem`
    - `ListEventosUseCase`
    - `EventoRepository.listWithStats`
  </artifacts>
  <key_links>
    - `EventoController.list` calls `ListEventosUseCase.execute`.
    - `ListEventosUseCase` consumes repository list rows and computes `ocupacao_percentual`.
    - Web hooks in later plans consume `EventoListItem`.
  </key_links>
</must_haves>

<decision_coverage>
- D-18: Event writes remain admin-only and backend-enforced.
- D-24: `StatusEventoEnum` remains the canonical runtime enum.
- D-25: Backend status values are not changed for display labels.
- D-26: Capacity/occupancy display is backed by API data, not invented in the UI.
</decision_coverage>
