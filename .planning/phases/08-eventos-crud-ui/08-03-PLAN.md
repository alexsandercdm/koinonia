# 08-03 - Shared event hooks and AppShell EventPill

<objective>
Create the shared event server-state boundary and replace the static shell event placeholder with a real event selector that all event-aware pages can share.
</objective>

<threat_model>
This plan reads event metadata into the authenticated shell. It must not expose event data to unauthenticated users and must not add write controls for non-admin users. Severity: medium before RBAC-aware UI, low after preserving ProtectedRoute and backend auth.
</threat_model>

<must_haves>
  <truths>
    - Event query keys are canonical and no longer duplicated in inscricoes/acomodacoes hooks.
    - `AppLayout` includes Eventos in desktop and mobile navigation.
    - EventPill uses real `/api/v1/eventos` data and selected event client state.
    - EventPill is display/selection only; server-side preferences remain out of scope.
  </truths>
  <artifacts>
    - `use-eventos.ts`
    - `eventosKeys`
    - `EventPill` inside or near `AppLayout`
  </artifacts>
  <key_links>
    - `AppLayout` consumes `useEventos`.
    - `use-inscricoes.ts` and `use-acomodacoes.ts` import/re-export event hook behavior from `use-eventos.ts`.
  </key_links>
</must_haves>

<decision_coverage>
- D-11: `/eventos` navigation is made discoverable through the authenticated shell.
- D-12: AppLayout navigation/header/EventPill follow the design-system shell contract.
- D-13: EventPill uses real `/api/v1/eventos` data and shared event query keys.
- D-14: selected event state remains client-side/local only.
- D-09: shell domain icons use Material Symbols Rounded where touched.
</decision_coverage>
