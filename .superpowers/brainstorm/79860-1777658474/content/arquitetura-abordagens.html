3 Abordagens Arquiteturais para Multi-Tenant

Escolha a estratégia de isolamento + RBAC que mais faz sentido para o Koinonia

A

Row-Level Isolation + Better Auth Organizations

Recomendada — Adiciona organization_id em todas as tabelas de domínio. Usa o plugin nativo de Organizations do Better Auth para gerenciar membros, convites e papéis por org. Hierarquia de papéis mapeada como roles customizadas dentro do Better Auth.

Prós

  • Aproveita infra de auth já existente
  • Self-service onboarding nativo (convites, org creation)
  • Migrations simples — Drizzle continua funcionando normalmente
  • Padrão adotado por 90% dos SaaS em estágio inicial

Contras

  • Requer guard de organization_id em toda query
  • Risco de vazamento de dados se query guard falhar
B

Row-Level Isolation + RBAC Customizado

Mesmo isolamento row-level, mas RBAC construído do zero no domínio: tabelas organizations, memberships, roles, permissions. Better Auth fica apenas para autenticação (JWT/sessões). Controle total sobre a hierarquia.

Prós

  • Controle total sobre hierarquia e permissões
  • Sem acoplamento a biblioteca de auth
  • Modelo de domínio explícito e auditável

Contras

  • Muito código a escrever (convites, memberships, etc.)
  • Fronteira auth/domínio fica ambígua
  • Reinventa o que Better Auth já oferece
C

Schema-per-Tenant + Better Auth Organizations

Cada organização recebe um schema PostgreSQL dedicado (org_uuid.eventos, org_uuid.pessoas…). Better Auth gerencia membership no schema público. Isolamento máximo — sem risco de cross-tenant query.

Prós

  • Isolamento máximo — impossível vazar dados entre orgs
  • Backup por org nativo
  • Sem necessidade de guard de org em queries

Contras

  • Migrations complexas — Drizzle não suporta multi-schema bem
  • Overkill para estágio inicial
  • Operacionalmente caro (100 orgs = 100 schemas)
  • Refactor profundo no código existente

Recomendação

Opção A — Better Auth já tem um plugin de Organizations maduro, com convites, roles e member management prontos. Isso economiza semanas de desenvolvimento e entrega self-service onboarding desde o dia 1. Row-level isolation com um guard centralizado no middleware do Fastify é o padrão da indústria nesse estágio.
